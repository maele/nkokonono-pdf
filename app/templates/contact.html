What to include in a support email

The more context you give, the faster we can help. Please include:

  • For bugs: the tool name (e.g. “Merge PDF”), what you expected, what happened, the error code shown (e.g. INVALID_FILE), and the browser and operating system.
  • For file-related issues: the approximate file size and page count, and whether the PDF was scanned, password-protected, or generated by a specific application.
  • For feature requests: the workflow you're trying to complete and why the current tools don't cover it.
  • For deployment help: your environment (Docker, bare-metal, cloud provider), and a description of what failed at which step.

We can help with

  • Bug reports on any of the {{ tools|length }} tools
  • Clarifications on tool behaviour or output quality
  • Self-hosting and deployment questions
  • Accessibility issues
  • Feature suggestions

We cannot help with

  • Recovering lost or accidentally-deleted documents
  • Password recovery on encrypted PDFs you can't open
  • Legal or compliance advice
  • Fixing documents that were corrupted before upload
  • Custom feature development (unless you're contributing it)

Reporting a security vulnerability

If you've found a security issue, please email {{ support_email }} with the subject line [Security]. Do not open a public GitHub issue for an unfixed vulnerability. Include reproduction steps and, if relevant, the affected tool and version.

Please do not send documents

Support is run by volunteers and email is not a secure channel. Please describe the problem rather than attaching the affected PDFs. If a specific document is required to reproduce a bug, we will ask for it — and you should only send it after removing sensitive content. Passwords should never be shared.
